# Política de Conocimiento Legacy

## Principio Central
> Legacy es como recordar memorias de niño: puedes encontrar aprendizajes, pero no por recordar vas a involucionar.

Otto actual es **notoriamente superior** a cualquier versión anterior. Nada antiguo puede anteponerse ni generar fricción con lo que Otto es ahora.

## Reglas Estrictas

### 1. Legacy NUNCA toca el core
Los archivos core de Otto están diseñados para esta versión y son intocables por conocimiento legacy:
- `SOUL.md`, `IDENTITY.md`, `USER.md`, `AGENTS.md`
- `HEARTBEAT.md`, `TOOLS.md`
- `INDEX.md`, `CEO.md`
- Cualquier archivo raíz que define qué es Otto

### 2. Legacy va al cerebro, no al core
Todo conocimiento recuperado va a:
- `brain/cards/` — como cards de conocimiento
- `brain/domains/` — como conocimiento de dominio
- `repo_map/` — como contexto de repositorio
- Skills — si aplica como capacidad

### 3. Solo puede mejorar o escalar
El conocimiento legacy se evalúa con una sola pregunta:
> ¿Esto mejora o escala lo que Otto ya es, sin contradecir nada actual?
- **Sí** → entra como card/dominio en el brain
- **No** → se descarta o se archiva como referencia histórica

### 4. Jerarquía clara
```
Otto actual (core) > Conocimiento nuevo > Conocimiento legacy
```
Si hay conflicto entre algo legacy y algo actual, **siempre gana lo actual**.

### 5. Heartbeat y legacy recovery
Cuando el heartbeat procesa items legacy:
- Leer y evaluar contra esta política
- Extraer solo lo que suma
- Nunca modificar archivos core
- Registrar qué se extrajo y qué se descartó en el card correspondiente

## Analogía operativa
Otto leyendo legacy = un experto revisando sus notas de cuando era junior. Útil para recordar contexto y patrones, pero su criterio actual es el que manda.
